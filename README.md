# Eliminating Digital Artifacts in Neural Piano Sustain Synthesis via Physical Constraints

[![PyTorch](https://img.shields.io/badge/PyTorch-2.0+-ee4c2c.svg)](https://pytorch.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

This repository contains the official PyTorch implementation and dataset for the paper: **"Eliminating Digital Artifacts in Neural Piano Sustain Synthesis via Physical Constraints"**. 

We propose a hybrid audio synthesis framework that eliminates the "digital artifacts" (such as temporal stuttering and frequency-domain aliasing) common in end-to-end neural networks when generating piano sustain pedal effects. This is achieved by explicitly injecting **dual-level physical constraints (mechanical and acoustic)** into the neural generation pipeline.

![System Architecture](NPPS_Architecture_Ready.png) 

## ✨ Key Features
- **Neural Perception Frontend**: Blindly extracts continuous pedal probabilities from unpedaled "dry audio" using a U-Net backbone.
- **Mechanical Constraint**: Introduces the Local Context-Aware Schmitt Trigger (LCAST) and asymmetric physical inertia to discipline the neural output, effectively eliminating high-frequency digital stuttering.
- **Acoustic Constraint**: Employs a Dual-Stage Decay engine and an anti-aliasing harmonic exciter to accurately reconstruct the energy dissipation and "spectral bloom" of sympathetic resonance.

## 📊 Experimental Results
Evaluated in a completely blind manner on the MAESTRO v3.0.0 dataset, our physically constrained system significantly outperforms the privileged industrial FluidSynth baseline in terms of macroscopic acoustic realism (FAD).

| Method | LCAST (Mechanical) | Dual-Stage (Acoustic) | RMS Corr (↑) | FAD (↓) |
| :--- | :---: | :---: | :---: | :---: |
| FluidSynth Wet (Privileged Baseline) | - | - | **0.2274** | 11.0834 |
| Ablation: w/o Dual-Stage | ✔ | ✖ | 0.0062 | 10.0246 |
| Ablation: w/o LCAST | ✖ | ✔ | 0.0143 | 9.8843 |
| **Proposed (Ours - Full)** | ✔ | ✔ | 0.0136 | **9.8853** |

## 📂 Data Preparation

To facilitate rapid reproduction of our experiments, we have uploaded the pre-processed dataset to Baidu Netdisk. The dataset contains the original MAESTRO v3.0.0 audio, the unpedaled Dry Audio (model input), and the privileged FluidSynth Wet audio for baseline comparison.

🔗 **Download Link**: [Baidu Netdisk](https://pan.baidu.com/s/1k78PrEl4aN1H_o7ivj6N3A)  
🔑 **Extraction Code**: `nipe`

After downloading, please extract the three folders and place them in the `data/` directory of this project. The file structure should look like this:

```text
Piano-Physical-Constraint-Synthesis/
├── data/
│   ├── maestro-v3.0.0/           # Original MAESTRO dataset (contains ground truth MIDI)
│   ├── maestro_dry/              # Pre-processed unpedaled dry audio (Model Input)
│   └── maestro_wet_fluidsynth/   # Industrial privileged baseline rendering results
├── src/
├── configs/
├── checkpoints/
├── NPPS_Architecture_Ready.png   # System Architecture Diagram
└── README.md
```

## 🚀 Usage

### 1. Inference and Audio Generation
To use the pre-trained model to generate wet audio with realistic pedal physical resonance from a given dry audio file:

```bash
python generate.py --config configs/default.yaml --input data/maestro_dry/sample.wav --output results/sample_wet.wav
```

### 2. Training from Scratch
If you wish to train the U-Net perception module from scratch, ensure the dataset paths are correctly configured in `configs/default.yaml`, and run:

```bash
python train.py --config configs/default.yaml
```

### 3. Visualization & Evaluation
Run the evaluation script to generate the LCAST mechanical motion comparison chart and the Spectral Bloom analysis plot, identical to those in the paper:

```bash
python evaluate.py --checkpoint checkpoints/best_pedal_net.pth
```
The generated figures will be saved in the `results/figs/` directory by default.
